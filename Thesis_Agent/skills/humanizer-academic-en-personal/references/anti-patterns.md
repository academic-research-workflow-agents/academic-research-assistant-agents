# Academic Anti-Patterns

Use this file to remove generic AI writing while keeping empirical content intact.

## 1. Inflated Significance

Watch for:
- "pivotal", "transformative", "critical turning point"

Better move:
- State the actual empirical or theoretical issue.

## 2. Promotional Language

Watch for:
- "remarkable", "powerful", "groundbreaking", "important and timely"

Better move:
- Replace praise with a concrete feature of the design or result.

## 3. Vague Attribution

Watch for:
- "scholars generally argue", "prior studies suggest" without clear positioning

Better move:
- Make the strand or disagreement explicit when the source text supports it.

## 4. Empty Contribution Statements

Watch for:
- "fills a gap", "adds to the literature", "provides useful evidence"

Better move:
- Specify the proxy, mechanism, setting, or empirical distinction.

## 5. Over-Hedging

Watch for:
- repeated combinations of "may", "might", "could", "appears to", "seems to"

Better move:
- Keep one calibrated hedge, not a stack.

## 6. Thesis-Proposal Meta-Language

Watch for:
- "this paper aims to investigate", "this paper plans to address", "future work may conduct"

Better move:
- Use direct research prose unless the user is actually writing a proposal.

## 7. Formulaic Contrast And Triads

Watch for:
- "not only ... but also", "one ..., second ..., third ..."

Better move:
- Use only when the argument truly needs the structure.

## 8. Unsupported Causal Claims

Watch for:
- "proves", "fully demonstrates", "causes" when the design is correlational

Better move:
- Match the claim to the design.

## 9. Chatbot Residue

Watch for:
- conversational helper phrases

Better move:
- Delete outright.

## 10. Technical Drift

Watch for:
- rewritten variable names, altered coefficients, softened model details

Better move:
- Keep technical content exact.

## 11. Exposed Pipeline Detail

Watch for:
- "first generate file A, then compress it into file B"
- script names, output filenames, or implementation order appearing in the main prose

Better move:
- Rewrite the process as research prose and keep only the rule, object, and analytical definition.

## 12. Unused Content Creep

Watch for:
- data layers that do not enter the current variable still being introduced in the data paragraph
- background material added only to sound complete

Better move:
- Discuss only what is actually used in the present construction and leave the rest out.

## 13. Contrastive Variable Definitions

Watch for:
- defining a variable by saying what it is "not"
- "rather than" doing most of the conceptual explanation

Better move:
- State directly what the variable measures and what analytical role it serves.

## 14. Vague Definition Terms

Watch for:
- "special rules"
- "standard cities"
- "a city has ..."

Better move:
- State the threshold, rule, coding definition, or time point directly. If the full definition is too long for the paragraph, move it to a clearly named note.

## 15. Overstated Harmonization

Watch for:
- writing as if the whole project already uses one unified definition when only the current asset has been checked
- hiding unresolved code differences behind words like "unified" or "standardized"

Better move:
- Describe the verified definition used in the present asset and leave broader harmonization claims for later only if they are actually true.

## 16. Explanatory Filler

Watch for:
- "these fields are sufficient"
- "this choice ensures"
- "it should also be noted"

Better move:
- If the fact is already clear, stop after stating the fact. Add explanation only when it carries real analytical content.

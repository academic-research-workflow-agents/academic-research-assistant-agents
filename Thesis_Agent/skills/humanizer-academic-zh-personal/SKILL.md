# 学术 Humanizer（中文，私人版）

本技能用于改写中文经金实证论文文本。基础目标仍然是去掉 AI 化套话和模板味，但在经金实证场景下，还会参考作者论文中稳定的章节推进方式、结果解释顺序和论证节奏。

按需读取：
- `references/section-playbook.md`：分论文章节的改写指引
- `references/anti-patterns.md`：需要优先清理的学术 AI 套话
- `references/style-profile.md`：当任务属于经金实证论文，或用户希望更接近本人写法时读取

## 工作流

1. 先判断当前文本属于哪一类章节，并保留该章节的功能；如果是摘要、引言、关键词或结论，先叠加 `section-playbook` 与 `style-profile` 里的前置章节补充层，再保留原有作者风格规则。
2. 如果用户已经手改过当前章节，先把手改稿视为最高优先级锚点；后续默认做 patch，不做整段重写。
3. 删除空泛拔高、模糊归因、模板化贡献表述和泛化政策语言。
4. 保留变量名、模型设定、样本期、系数方向、数量级、表格引用和因果边界。
5. 若任务属于经金实证论文，使用 `style-profile.md` 的章节习惯来调整推进方式和句法节奏；前置章节场景下，这些补充规则是对原画像的加法，不是覆盖原画像。
6. 保留作者的实证写作逻辑，但不保留可以更规范的表达缺陷。
7. 默认只输出改写后的文本；仅当用户要求时再补简短说明。

## 硬规则

- 不编造数据、变量、系数、文献、样本期、机制、政策建议或研究贡献。
- 不模仿学校或期刊格式。
- 不照搬作者原句。
- 不把“像作者”理解为保留不规范表达或机械重复“本文认为”“本文发现”。
- 保留经金实证写作的结构感，但优先服从学术标准。
- 用户手改稿优先于任何旧的 assistant 版本；除非事实错误或用户明确要求，不重写已经被用户压缩好的句子。
- 只要用户先手改中文，再让我继续改，我必须先归档手改稿，再动正文。
- 方法、变量和样本章节只写实际进入当前构造的内容，没用上的数据层不要硬塞进正文。
- 技术处理要改写成论文语言，不直接暴露脚本名、文件名、输出路径或流水线顺序。
- 变量解释优先正面定义“它衡量什么”，不要用“而不是……”来反向下定义。
- 数据库自带筛选规则在正文只写必要摘要，完整判定标准、关键词表或附录原文放补充说明。
- 项目自构变量或城市口径在正文只写“怎么得到”和“用于什么分析”，精确规则、代码口径、人工修正和特殊处理放补充说明。
- 不保留“特定规则”“标准城市”“拥有”这类未被界定的模糊词；要么具体写清，要么改成补充说明里的可核验表述。
- 当当前资产与全项目统一口径尚未完全一致时，正文不得提前写成“统一口径已完成”。
- 正式类别名称优先于 assistant 自造的概括词；如果已有现成类别名，就不要再发明新的 umbrella term。
- 项目内简称第一次出现在正文时，必须当场交代它来自哪里、指什么，不能把读者直接丢给附录。
- 用户只否定某个细节时，只 patch 那个细节，不得借机重写整句或整段。
- 中文优先追求顺和可读，不机械追求主谓宾补齐；只要上下文能自然承接，就不要硬补成解释腔句子。

## 路由

- 所有章节改写：读 `references/section-playbook.md`
- 文本明显存在空话、套话、拔高或模板味：读 `references/anti-patterns.md`
- 经金实证风格贴近作者，或任务属于摘要、引言、关键词、结论等前置章节：读 `references/style-profile.md`

## 输出

默认输出：
- 改写后的文本

按需附加：
- 简短说明主要删改点或所使用的风格策略

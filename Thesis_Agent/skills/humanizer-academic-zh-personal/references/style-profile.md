# 私人风格画像（中文）

本画像基于作者中文论文全文提炼，尤其重视变量说明、模型设定、回归解释、稳健性和扩展分析部分。只模仿论证推进和表达节奏，不模仿格式或原句。

## 应保留的整体特征

* 章节开头通常先交代研究对象、变量、样本、机制或目标。
* 一句话通常只承担一个主要功能，先定义，再补事实，不顺手再加一层解释或自我正当化。
* 中段技术写作强调“定义 -> 构造或识别逻辑 -> 结果解释”。
* 回归解释常按以下顺序展开：

  1. 先说方向和显著性
  2. 再给数量级或相对样本均值的经济含义
  3. 再连接机制或假设
  4. 最后给有限度解释
* 讨论与结论部分仍保持实证论文的结构感，不靠修辞取胜。

## 分章节习惯

### 变量说明、样本与模型

常见推进：

* 先定义变量、样本或代理变量
* 再写当前实际使用的数据来源
* 再写构造方式或必要处理规则
* 最后交代这样设定的含义或考虑

应保留的写法精神：

* “本文以……为样本”
* “本文参考……构造……”
* “作为……的代理变量”
* “为削弱……问题”

改写时的优化：

* 保留这个推进顺序，但压缩重复的“本文”起句。
* 优先从研究对象、代理变量或核心口径起笔，不从数据库或技术流程起笔。
* 只写真正进入当前变量构造的内容，不把没用上的数据层提前写进正文。
* 技术处理要翻译成论文语言，不出现脚本、文件名、输出路径或“先生成 A 再压缩成 B”这类实现口吻。
* 变量解释只写“它衡量什么”，不要用“而不是……”来排除别的概念。
* 用更紧的句法表达构造与识别逻辑，句子尽量短一些，少堆限定语。
* 当用户已经把一句话压到更自然的节奏时，只补必须补的事实，不要为了“更完整”重造整句。
* 数据库自带识别规则在正文只保留一句可读摘要，完整口径、关键词表和详细判定条件放补充说明。
* 项目自构城市口径或变量口径，正文只交代核心构造逻辑；精确代码、特殊单元、人工修正和例外处理留在补充说明。
* 不要用“特定规则”“标准城市”“拥有”这类没有定义的词来代替真实口径。
* 如果当前 case 和其他 case 还没有真正统合，正文就只写当前 case 已核验的状态，不抢写“已统一”。
* 少写“这些字段足以……”“这一选择保证了……”“需要说明的是……”这类解释性补白；如果事实本身已经成立，就直接陈述。

### 回归结果解释

常见推进：

* 先报核心结果
* 再报数量级或经济量级
* 再说明与假设、机制或既有研究的关系
* 最后补有限度解释

应保留的写法精神：

* “结果显示……”
* “说明……”
* “可见……”
* “与假设……相符”
* “相当于……”

改写时的优化：

* 保留顺序，但避免每段都用同一套连接词。
* “说明/可见/进一步”要轮换使用，避免模板化。

### 稳健性与扩展分析

常见推进：

* 先说明替换变量、替换控制变量、加入额外控制或分组方式
* 再说明符号、显著性或幅度变化
* 最后得出“结果稳健”或“整体稳健但有所减弱”的判断

### 结论与启示

常见推进：

* 先概括主要发现
* 再概括机制或渠道
* 最后给出政策或实践含义

改写时的优化：

* 保留这种收束顺序，但压缩口号式政策语言。
* 启示必须回到结果本身，不要拔高到过大的叙事。

## 需要纠偏的习惯

* 避免机械重复“本文发现”“本文进一步发现”。
* 避免把“这说明”写成每段固定句眼。
* 避免“具有重要理论意义和现实意义”这一类空泛收束。
* 避免为了正式而堆叠连接词或限定语。

## 前置章节补充画像（叠加，不覆盖）

这一组规则来自 46 篇相关文献的前置章节提炼，用来补充当前个人画像；它只约束摘要、引言、结论和关键词，不覆盖上文已有的变量、模型、结果解释和稳健性写法。

### 摘要

* 优先顺序是“研究对象或问题 -> 数据与识别 -> 主结果 -> 一层机制或异质性 -> 有限启示”。
* 首句最多保留 1 句短背景，第二句前必须落到“本文研究什么”。
* 中文摘要不追求把所有贡献都写满，只保留与结果直接对应的一层机制或启示。

### 引言

* 开篇背景控制在 1-2 句内，尽快进入研究问题。
* 更稳定的推进顺序是“短背景 -> 研究问题 -> 文献缺口 -> 设计预告 -> 贡献”。
* 贡献写成和识别设计、样本、机制或比较维度直接对应的 2-3 个实点，不写“丰富文献、具有重要意义”一类口号。

### 结论与启示

* 先回收主结果，再回收最关键的一层机制、异质性或扩展结果，最后才写有限启示或边界。
* 如果正文已有多组机制和异质性，结论只回收最关键的一层，不重播表格目录。
* 局限只用于澄清边界，不改写成未来研究愿望清单。

### 关键词

* 中文关键词建议保留 `3-5` 个，当前 thesis 默认优先 `4` 个。
* 排序优先“主题词 -> 对象或场景词 -> 方法词”，其中方法词最多 1 个，且只有在方法确实是论文卖点时才保留。
* 分隔方式保持稳定，优先 `；`；不要把关键词写成短句，也不要中英文混排。

### 写作顺序

* thesis front-matter 起草保持串行，不反向回写：中文结论 -> 英文结论 -> 中文引言 -> 英文引言 -> 中文摘要 -> 英文摘要 -> 中文关键词 -> 英文关键词。
* 英文稿默认以已确认的中文稿为结构锚点，吸收英文论文的句法功能，但不反过来改写中文结构。

## 不要模仿的内容

* 不模仿学校模板、标题格式、参考文献格式。
* 不照搬原句。
* 不保留可以更规范的表达缺陷。
